# Test sheet: NHL94AGA 0.5.0 (phase P5, the game's logic on the A1200)

About 45 to 90 minutes, mostly waiting. Run it on a **real A1200** (PROMPT.md rule 2). There is no
picture or sound yet. The program plays the repository's seven input scripts through the game's own C.
After every pass it checks work RAM against the reference and times the pass (gate A-LOGIC and the
feasibility measurement, PROMPT.md 6.5). Run 0.1.0's sheet first if you have not.

## The disks (private: made from your ROM, do not share them)

* `nhl94-aga-v0.5.0-private-verify.adf`: boots into the check. It holds `NHL94VFY`, the scripts, and
  `refs/` (the reference hashes, made from your ROM on the host).
* `nhl94-rom-a.adf` and `nhl94-rom-b.adf`: your cartridge in two halves (volumes `NHL94ROMA` and
  `NHL94ROMB`), for an A1200 with only floppies. With a hard disk or a CF card instead, copy your
  1 MB ROM there as `nhl94.bin` on a volume or assign named `NHL94ROM:`, or put it in `RAM:nhl94.bin`
  (this needs Fast RAM: with 2 MB of Chip RAM alone, RAM: cannot hold it beside the program).

The public `nhl94-aga-v0.5.0.adf` is not handed out. The game's compiled C carries some of the
cartridge's tables, so it fails A-LEGAL (decision D-12 in STATUS.md).

## Steps

1. **Boot the verify disk** with nothing else attached that you would not count as stock. Write down
   every expansion.
2. It prints its version, Kickstart, CPU and free memory. Then it says
   `ROM: insert the disk NHL94ROMA when asked, then NHL94ROMB`. Swap disks when AmigaDOS asks, and put
   the verify disk back when it asks for `NHL94AGA`.
3. It checks the ROM (`ROM: the US/Europe cartridge (CRC32 9438F5DD)`) and plays the scripts one by one:
   attract (7199 frames), full_game (15999), playoff_game (14999), records_game (15699), pause_menus
   (8599), shootout_menus (4799), name_entry (2999). The screen stays on the Shell. Every 1200 frames it
   prints a line such as `full_game: frame 2400, 0 differ`. **Do not touch the mouse.** The left button
   skips the current script.
4. After each script it prints a summary line:
   ```
   attract: 7199 frames, 0 differ; pass time max N us (P% of a frame) at frame F, mean M us, X over 90%, Y over 100%; power-on pass Z us
   ```
5. At the end: `A-LOGIC: PASS (7 scripts, 0 differing frames)`. The log is written to `NHL94VFY.log`
   on the verify disk (or `RAM:` when the disk is write-protected).
6. If you have a null-modem cable and a PC, the same lines also come out of the serial port at 9600
   baud, 8N1, as the check runs. Capture them as well.
7. Optional, if you have one: run it once more with Fast RAM fitted, and write down that it was not
   stock.

## What to send back

* `NHL94VFY.log` (and the serial capture if you made one).
* This table:

| Run | Kickstart | Machine and expansions | ROM from (floppies, HD, CF) | A-LOGIC | Worst pass, us (% of frame) | Passes over 100% | Notes (Guru numbers, hangs) |
|---|---|---|---|---|---|---|---|
| 1 | | | | | | | |

How to read it:

* **A-LOGIC FAIL** with `first difference at frame N`: send the log. The gate fails, and the unit goes
  back with your numbers.
* **The pass times** are the feasibility gate (PROMPT.md 6.5). They are the game's logic alone, under
  the OS, from Chip RAM. The display, sound and input still have to fit in what is left of the frame,
  with 10% to spare. If the worst pass is already near 100%, P5's decision goes to you (D-4, hot-spot
  assembly, or Fast RAM as a requirement). Nothing is slowed down or skipped quietly.
* A Guru Meditation or a hang: write down its number and the last line printed.
