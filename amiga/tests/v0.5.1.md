# Test sheet: NHL94AGA 0.5.1 (phases P5 and P6.1: faster logic, and the display requests checked)

About 60 to 100 minutes, mostly waiting. Run it on a **real A1200** (PROMPT.md rule 2); with Fast RAM
fitted if you have it (the baseline, D-14), and once without if you can. There is no picture or sound
yet. Run 0.1.0's sheet first if you have not. Everything 0.5.0's sheet said about the ROM (two floppies,
or `NHL94ROM:nhl94.bin`, or `RAM:nhl94.bin`) still holds.

## The disks

Private, made from your ROM by `make -C amiga verify-disks`; do not share them:

* `nhl94-aga-v0.5.1-private-verify.adf`: boots into the logic check (gate A-LOGIC) and the pass times.
* `nhl94-aga-v0.5.1-private-intent.adf`: the same disk with the display requests' reference hashes
  (gate A-DISPLAY-INTENT).
* `nhl94-rom-a.adf`, `nhl94-rom-b.adf`: your cartridge in two halves.

The public `nhl94-aga-v0.5.1.adf` carries no reference hashes. On it, the program writes its hashes
beside itself (`NAME.h32`, and `NAME.i32` with `INTENT`) for `amiga/tools/h32compare.py` on a PC. The
disk has room for one kind at a time: delete the `.h32` files before an `INTENT` run.

## Steps

1. **Logic and timing.** Boot the verify disk and let all seven scripts run, as in 0.5.0's sheet. It
   ends with `A-LOGIC: PASS (7 scripts, 0 differing frames)`. Keep `NHL94VFY.log` and the seven
   `NAME.over` files it writes.
2. **Display requests.** Boot the intent disk, press Ctrl-C at the first line to stop its
   Startup-Sequence (or let the logic run pass by and wait), then type `NHL94VFY INTENT`. It ends with
   `A-DISPLAY-INTENT: PASS (7 scripts, 0 differing passes)`. Keep its `NHL94VFY.log` too. In this mode
   the pass times include the hashing and do not count.
3. **Optional, one pass profiled** (only if asked for a number): `NHL94VFY name_entry PROFILE 1227 1227`
   writes `name_entry.prof`. The screen goes black while it samples and comes back.
4. Optional: step 1 once more without Fast RAM, written down as stock.

## What to send back

* Both `NHL94VFY.log` files, the `.over` files, and any `.prof`.
* This table:

| Run | Kickstart | Machine and expansions | A-LOGIC | A-DISPLAY-INTENT | Mean pass, us (full_game / records_game) | Longest pass, ms | Notes (Guru numbers, hangs) |
|---|---|---|---|---|---|---|---|
| 1 | | | | | | | |

How to read it:

* **Either gate FAIL**: send the log. The unit goes back with your numbers.
* **The pass times** are the game's logic alone, under the OS. On a PC, `amiga/tools/speedcheck.py
  NAME.over out/vectors/NAME.lockstep` compares the long passes with the cartridge's own and counts the
  ones that ran over a frame with a picture on screen (D-15). Emulated, with 8 MB Fast RAM, the figures
  to compare with are: mean 1.0 to 3.9 ms, longest 305 ms, never later than the cartridge.
* A Guru Meditation or a hang: write down its number and the last line printed.
